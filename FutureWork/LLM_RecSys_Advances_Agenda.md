# Recent Advances in LLM Powered Recommender Systems

This proposed series follows up on [Building Recommender Systems Using Large Language Models](https://link.springer.com/book/10.1007/978-3-032-01152-7). The book introduces LLM-enhanced, end-to-end, conversational, and multimodal recommendation. The series will examine how recent systems choose where to use LLMs, what signals they learn from, and how they measure quality, latency, and cost.

## Proposed agenda

1. **From content tagging to pairwise relevance.** Compare category overlap, embedding similarity, and human-reviewed relevance judgments on the same item pairs. Reddit’s move from IAB category matching to direct post–ad relevance gives a concrete example. A companion exercise could ask whether a template meets a design brief and score that separately from correct category assignment. [Reddit Engineering](https://www.reddit.com/r/RedditEng/comments/1r0hyfu/contextual_relevance_of_ads_reddit/)
2. **Multimodal content understanding and evolving taxonomies.** Compare hierarchical routing with cross-branch candidate retrieval and evidence-based label validation. For unmatched items, use rolling clustering and human review to propose new concepts, merges, or aliases. Evaluate candidate recall, labeling accuracy, and usefulness for downstream retrieval. [TaxoAdapt](https://aclanthology.org/2025.acl-long.1442/) · [BERTopic](https://arxiv.org/abs/2203.05794)
3. **User modeling with behavior sequences and textual profiles.** Explore how recent actions, explicit intent, and durable preferences enter a recommender. Pair LinkedIn’s textual user representation work with Feed SR, noting the different applications and evidence. Consider recency, privacy, and the cost of assembling context. [Textual User Representation](https://arxiv.org/abs/2602.07333) · [LinkedIn Feed SR](https://arxiv.org/abs/2602.12354)
4. **Vector retrieval and generative retrieval with Semantic IDs.** Compare nearest-neighbor search and TIGER-style generation on the same catalog. Cover vector indexing and projection tradeoffs, catalog updates, and prefix-constrained decoding. Measure Recall@K, invalid IDs, cold-start performance, and retrieval latency. [TIGER](https://arxiv.org/abs/2305.05065) · [Understanding Semantic IDs](https://arxiv.org/abs/2607.24995)
5. **LLM ranking in production.** Compare an offline relevance judge and distilled ranker with an LLM-backed ranker. Use LinkedIn Semantic Search and Netflix GenRec to discuss context engineering, training supervision, throughput, and where to spend the inference budget. [LinkedIn Semantic Search](https://arxiv.org/abs/2602.07309) · [Netflix GenRec](https://arxiv.org/html/2608.10257v2)
6. **Reinforcement learning with verifiable rewards for re-ranking.** Compare the incoming rank order, supervised re-ranking, and reward-driven re-ranking. Use GR2 to show how a format reward can favor copying the incoming order and how conditional rewards address that shortcut. Test ranking gains on shuffled candidate lists and discuss what click-derived rewards capture. [Meta GR2](https://arxiv.org/abs/2606.31984)
7. **Evaluating conversational and agentic recommendation.** Test when the system should ask a question, retrieve more evidence, or present a shortlist. Measure constraint satisfaction, task completion, interaction turns, latency, and cost. Adapt task and harness evaluation ideas from AgenticVBench to recommendation-specific scenarios. [AgenticVBench](https://agenticvbench.com/)

## Suggested first installments

Start with **pairwise relevance**, **Semantic IDs**, and **reward design for re-ranking**. These topics lend themselves to distinct, reproducible exercises that can accompany articles or videos. Each installment can begin with a production decision, compare methods on the same data, and report what changes in quality, latency, and cost.
